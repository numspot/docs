# VM types

The types of [VM (Virtual Machine)](/docs/compute/concept/) determine the hardware characteristics of your VM.

When you create a VM, you must specify a VM type. It remains modifiable afterwards, however.

## Characteristics

A VM type determines the hardware characteristics of your VM, among which are:

* Compute characteristics: CPU (Central Processing Unit) generation, number of vCPU (virtual Central Processing Unit), amount of memory and performance indicator.
* Network characteristics: maximum number of NIC (Network Interface Card) you can attach and maximum number of private IP (Internet Protocol) you can assign per NIC.

The CPU generation corresponds to a family of Intel CPUs:

{/* v5 : Intel Skylake */}
* v6: Intel Ice Lake
{/* v7 : Intel Sapphire Rapids */}
To learn more about these CPU families, see the [official Intel documentation](https://ark.intel.com/content/www/fr/fr/ark.html).

The performance indicator is a value that determines the overall performance of the vCPU:

* 1 (Highest): maximum compute capacity on all the vCPU of the VM. This value is ideal for compute-intensive applications requiring stable performance throughout the life cycle of the VM.
* 2 (High): high compute capacity on all the vCPU of the VM. This value applies to most cases and offers performance that varies over time.
* 3 (Moderate): performance that varies significantly on all the vCPU of the VM. This value does not guarantee consistent performance, but is ideal for machines with low CPU demand.

## Available VM types

Numspot offers a wide range of VM types optimized for different use cases.

These instance types correspond to different combinations in terms of processor (CPU), memory and networking capabilities. You can thus choose a set of resources perfectly suited to your applications. 

Each VM type includes one or more VM sizes, which lets you scale your resources according to the requirements of the target workload. This flexibility lets you select the most appropriate VM type to meet the needs of your applications, and to adapt it as those needs evolve.

### Economy use (Economic) 
Offering an optimal cost-performance ratio, they suit workloads with moderate processor and memory resource needs. <br/>
They are perfect for web servers with low or medium load, development and test environments, or applications with inconsistent demand. <br/>
They are also ideal for low-demand tasks, such as static web servers, low-traffic websites and microservices.

### Memory use (Memory)
High-memory-capacity VM are specially designed for workloads that require a large amount of RAM (Random Access Memory). <br/>
They are ideal for in-memory databases, caching systems, real-time data-processing operations, relational databases and large-data analysis applications. <br/>
These VM generally offer a high number of gigabytes of RAM per processor core, making them perfectly suited to memory-intensive workloads, such as in-memory caches and analytics applications.

### Inference use (Inference)  
Inference VM are optimized for inference workloads, offering high performance for running artificial-intelligence models in production.
They use high-performance processors — CPU or [GPU (Graphics Processing Unit)](/docs/compute/gpu/concept/) as needed — to ensure minimal latency and high throughput when processing large volumes of requests.
These VM are particularly suited to use cases such as real-time prediction, embedded data analysis, image or natural-language processing, as well as the deployment of machine learning models optimized for inference at scale.
