# Versions et cycle de vie

Numspot opère ses [clusters Kubernetes](/docs/managed-services/kubernetes/concepts/) avec des versions stables bénéficiant d'un suivi actif des correctifs de sécurité, en conformité avec les exigences de sécurité appliquées au service.

## Versions supportées

La version mineure suivante est supportée :

- **Kubernetes 1.34**

Ce périmètre couvre les versions stables et activement maintenues par la communauté Kubernetes, avec un suivi continu des bulletins de sécurité.

:::note
Lors de la création d'un cluster, la version la plus récente est sélectionnée par défaut. Pour plus d'informations, consultez [Créer un cluster Kubernetes](/docs/managed-services/kubernetes/actions/create/).
:::

## Suivi des patches de sécurité

Les images utilisées pour les clusters Kubernetes intègrent :

- Des mises à jour de correctifs (patch) appliquées régulièrement pour corriger les bugs et les failles de sécurité.
- Un suivi actif des vulnérabilités critiques et hautes.
- Une image système durcie suivant les recommandations de l'ANSSI.

Les mises à jour de correctifs sont appliquées automatiquement par Numspot et ne nécessitent aucune action de la part du client. Elles ne concernent que les versions patch (par exemple, `1.34.0` vers `1.34.1`), sans modification de la compatibilité des données.

:::info
Pour obtenir des informations sur les versions appliquées ou les correctifs récents, contactez le support Numspot.
:::

## Cycle de vie des versions (lifecycle)

### Politique de support

| Version | Statut du support | Date de fin de support communautaire | Fin de support Numspot estimée |
|---------|-------------------|--------------------------------------|--------------------------------|
| **1.34** | Active | février 2027 | février 2027 |

Le statut de support est aligné sur les dates annoncées par le projet Kubernetes. Numspot suit la politique Kubernetes concernant le support des versions mineures.

### Notification de fin de support

Numspot notifie ses clients **plusieurs mois avant la fin de support** d'une version mineure. Cette notification permet aux clients de planifier la migration vers une version plus récente.

## Mises à jour mineures

Les mises à jour mineures (par exemple, de Kubernetes 1.33 vers Kubernetes 1.34) nécessitent la mise à jour du cluster. Numspot recommande de tester la compatibilité de vos applications avant de procéder à une mise à jour mineure.

:::warning
Numspot ne peut pas garantir la compatibilité ascendante entre les versions mineures. Il est de la responsabilité du client de vérifier que ses applications sont compatibles avec la nouvelle version avant toute migration.
:::
