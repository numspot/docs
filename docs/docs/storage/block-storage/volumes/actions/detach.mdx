# Detach a volume

You can detach a `volume` from a [VM (Virtual Machine)](/docs/compute/concept/), which allows you to attach it to another VM and access your data again.

:::warning
For Linux VM, the `volume` mount must be permanent to avoid any failure when the VM starts.
:::

## Permissions

:::info
This action requires the following **IAM** (Identity and Access Management) permissions:

- **compute.blockStorage.update**

:::

<Tabs>
<TabItem value="Console" default>

1. Log in to the Numspot console.
2. From the left-hand side menu, click **Storage** → **[Block Storage](/docs/storage/block-storage/concepts/)** → **Volumes**. The list of `volumes` appears.
3. Select the `volume` that you want to link.
   :::info
   You can also select a VM in the "VM" dashboard and click **Detach a volume**.
   :::
4. Under the `volume` actions menu, click **Dissociate from the VM**.
   :::warning
   Detaching a `volume` to which data is being written may damage your resources.

   You can detach a system `volume` from a VM if this VM is stopped. However, you will not be able to restart this VM using this system `volume`.
   :::
   The **Volume dissociation** dialog box appears.

5. Click **Dissociate the volume**.

   A confirmation message appears.

   The `volume` is detached from the VM.

</TabItem>
<TabItem value="API">

The `PUT /compute/spaces/{spaceId}/volumes/{id}/vms/unlink` command detaches a block storage `volume` from a VM. To detach the root device of a VM, this VM must be stopped.

[Request example: Detach a Volume from a VM ↗](/openapi/#tag/compute/PUT/compute/spaces/{spaceId}/volumes/{id}/vms/unlink)

</TabItem>
