# Create a volume

You can create `volumes` that you can attach to [VM (Virtual Machine)](/docs/compute/concept/) created within the same Sub-region. `volumes` allow you to add storage capacity to a VM if the system `volume` has reached its maximum storage capacity, or to separate your data storage from the VM operating system files.

## Permissions

:::info
This action requires the following **IAM** (Identity and Access Management) permissions:

- **Section:** compute — **Permission:** `blockStorage.create` (create the volume)
- **Section:** compute — **Permission:** `blockStorage.get` (view the volume after its creation)

:::

1. Log in to the Numspot console.
2. From the left-hand side menu, click **Storage** → **[Block Storage](/docs/storage/block-storage/concepts/)** → **Volumes**.
3. Click **Create a volume**. The "Volume creation" page appears.
4. In the "Sub-region (Availability zone)" list, select the Sub-region in which you want to create the `volume`.
5. In the "Name" field, type a name for the `volume`.
   :::info
   This action adds a Name tag of up to 255 characters. You can use any characters, including accented letters.
   :::
6. In the "Size" field, type the size of the `volume`.
   :::warning
   The minimum size allowed for a `volume` is:
   - 1 GiB for 'standard';
   - 1 GiB for 'gp2';
   - 4 GiB for 'io1'.

   The maximum size allowed for a `volume` is 14901 GiB.
   :::
7. In the "Type" list, select a `volume` type:
     - `standard` for a Magnetic `volume`;
     - `io1` for an Enterprise `volume`;
     - `gp2` for a Performance `volume`.
8. (io1 volumes only) In the "IOPS" field, type the number of IOPS (Input/Output Operations Per Second) for the `volume` or select it using the arrows.
   :::warning
   The maximum number of IOPS allowed for io1 `volumes` is 13,000, with a maximum performance ratio of 300 IOPS per gibibyte.
   :::
9. In the "Number" field, type the number of `volumes` you want to create.
10. In the "Snapshot" list, leave "None" selected.
11. Click **Create a volume**.
    The `volume` is created.

## API {#tabhead-api}


Create a block storage `volume` within a space, either empty or restored from an existing snapshot. The `volume` can then be attached to a VM in the same sub-region.

:::info
**Prerequisites**: none. To restore a `volume` from a snapshot, the latter must exist ([create a snapshot ↗](/docs/storage/block-storage/snapshots/actions/create)).

This operation requires an [access token](/docs/iam/concepts/api/) and the permissions listed at the top of the page.
:::

`POST https://api.eu-west-2.numspot.com/compute/spaces/{spaceId}/volumes`

[Full documentation for this endpoint ↗](/openapi/#tag/compute/POST/compute/spaces/%7BspaceId%7D/volumes)

### Parameters

| Parameter | Location | Required | Type | Example | Description |
| --- | --- | --- | --- | --- | --- |
| `availabilityZoneName` | body | yes | enum | `eu-west-2a` | Sub-region of the `volume`: `eu-west-2a`, `eu-west-2b`, `eu-west-2c`, `cloudgouv-eu-west-1a`, `cloudgouv-eu-west-1b` or `cloudgouv-eu-west-1c` |
| `spaceId` | path | yes | UUID | `123e4567-e89b-12d3-a456-426614174000` | Space in which to create the `volume` |
| `iops` | body | `io1` only | integer | `100` | Provisioned IOPS, 13000 maximum, 300 IOPS per GB ratio |
| `size` | body | unless snapshot | integer | `10` | Volume size, in GB, 14901 maximum |
| `snapshotId` | body | unless size | string | `snap-12345678` | Identifier of the snapshot to restore |
| `type` | body | no | string | `gp2` | `volume` type: `io1` (Enterprise), `gp2` (Performance) or `standard` (default) |

The types used in this table are described in the [Parameter types](/docs/reference/parameter-types) page.

### Example

```bash
export TOKEN="{TOKEN}"

curl 'https://api.eu-west-2.numspot.com/compute/spaces/{SPACE-ID}/volumes' \
  --request POST \
  --header "Authorization: Bearer $TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{
  "availabilityZoneName": "{AVAILABILITY-ZONE-NAME}",
  "size": 10,
  "type": "gp2"
}'
```

| Variable | Represents | Where to find its value |
| --- | --- | --- |
| `{TOKEN}` | OAuth 2.0 access token of the request | Generated by the API authentication flow (see [Access token](/docs/iam/concepts/api/)) |
| `{SPACE-ID}` | Numspot space in which to create the `volume` | Numspot console (active space) or response of the [List spaces ↗](/docs/iam/space/actions/list) API |
| `{AVAILABILITY-ZONE-NAME}` | Sub-region of the `volume` | One of the six sub-regions listed in the parameter table above |

### Response

`201 Created` — the payload describes the created `volume`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Volume identifier (`vol-…`) |
| `availabilityZoneName` | string | Sub-region of the `volume` |
| `size` | integer | Size, in GB |
| `type` | string | `standard`, `gp2` or `io1` |
| iops | integer | Provisioned IOPS (`io1`) or baseline performance (`gp2`) |
| `state` | string | `creating`, `available`, `in-use`, `updating`, `deleting` or `error` |
| `snapshotId` | string | Snapshot the `volume` was restored from, if any |
| `linkedVolumes` | array | VM attachment information |
| `tags` | array | Associated tags (including the "Name" tag) |
| `creationDate` | string | Creation date |

```json
{
  "availabilityZoneName": "eu-west-2c",
  "creationDate": "2026-09-21T10:15:30.485Z",
  "id": "vol-12345678",
  "iops": 100,
  "linkedVolumes": [],
  "size": 10,
  "state": "creating",
  "tags": [
    {
      "key": "Name",
      "value": "my-volume"
    }
  ],
  "type": "gp2"
}
```

:::info
The creation is asynchronous: the `volume` is returned with the `creating` state, then moves to `available` when ready. To track the state, call the [read the volumes of a space endpoint ↗](/openapi/#tag/compute/GET/compute/spaces/%7BspaceId%7D/volumes).
:::

### Main errors

| Code | Case |
| --- | --- |
| 400 | Invalid body: size out of the `volume` type bounds (14901 GB maximum), iops provided with a type other than `io1`, iops above 13000 or ratio above 300 IOPS per GB |
| 401 | Access token missing, expired or invalid |
| 403 | Missing `blockStorage.create` permission |
| 404 | Unknown `spaceId` |
| 500 | Internal service error — retry later |

## Terraform {#tabhead-terraform}


Manage the `volume` with the `numspot_volume` resource of the [Numspot Terraform provider ↗](https://registry.terraform.io/providers/numspot/numspot/latest/docs). The provider authenticates with a service account's credentials (client_id / client_secret) and operates at space level.

:::info
**Prerequisites**: none. The `volume` can be attached to a VM at creation time through `link_vm`: the VM and its subnet must then exist.

The required permissions are listed at the top of the page.
:::

### Example

```hcl
terraform {
  required_providers {
    numspot = {
      source = "numspot/numspot"
    }
  }
}

variable "client_id" {
  type = string
}

variable "client_secret" {
  type      = string
  sensitive = true
}

provider "numspot" {
  client_id     = var.client_id
  client_secret = var.client_secret
}

resource "numspot_volume" "volume" {
  type                   = "standard"
  size                   = 11
  availability_zone_name = "eu-west-2a"
  tags = [
    {
      key   = "name"
      value = "My Volume"
    }
  ]
}
```

| Variable | Represents | Where to find its value |
| --- | --- | --- |
| `var.client_id` | Service account identifier used by the provider | Created when the service account is created (Numspot console, IAM section) |
| `var.client_secret` | Service account secret | Generated when the service account is created, to be kept in a secrets manager |

### Arguments

| Argument | Required | Type | Example | Description |
| --- | --- | --- | --- | --- |
| `availability_zone_name` | yes | string | `eu-west-2a` | Sub-region of the `volume`: `eu-west-2a`, `eu-west-2b`, `eu-west-2c`, `cloudgouv-eu-west-1a`, `cloudgouv-eu-west-1b` or `cloudgouv-eu-west-1c` |
| iops | `io1` only | number | `100` | Provisioned IOPS, 13000 maximum, 300 IOPS per GiB ratio |
| `link_vm` | no | object | `{vm_id = "i-12345678", device_name = "/dev/sdb"}` | Attaches the `volume` to a VM at creation time (`vm_id`, `device_name`) |
| `replace_volume_on_downsize` | no | bool | `false` | Recreates the `volume` when its size is reduced |
| `size` | unless snapshot | number | `11` | Size, in GiB, 14901 maximum |
| `snapshot_id` | unless size | string | `snap-12345678` | Identifier of the snapshot to restore |
| `tags` | no | set | `{key = "name", value = "my-volume"}` | Key/value tags associated with the `volume` |
| `type` | no | string | `standard` | `volume` type: `standard`, `gp2` or `io1` |

The types used in this table are described in the [Parameter types](/docs/reference/parameter-types) page.

### Import

If the `volume` already exists (created via the console or the API), import it into the Terraform state instead of recreating it:

```bash
terraform import numspot_volume {VOLUME-ID}
```

`{VOLUME-ID}` is the `volume` ID (`vol-…`, visible in the console or in the API response). The command attaches the existing resource to the matching `resource "numspot_volume"` block in your configuration, without modifying it. Terraform does not generate the configuration: afterwards, check with `terraform plan` that your configuration describes the actual state, or the next `apply` may destroy or modify the resource unexpectedly.
