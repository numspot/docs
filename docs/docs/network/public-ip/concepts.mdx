# À propos des IP publiques

<ActionsSummary />

Une IP publique (Public IP) est une adresse IPv4 que vous pouvez allouer à votre compte, pour ensuite l'associer à l'une de vos ressources.

Vous pouvez dissocier une IP publique de sa ressource à n'importe quel moment, puis la ré-associer à une autre.

## Informations générales

Les IP publiques sont des adresses IPv4 publiques que vous pouvez allouer à votre compte. Vous pouvez ensuite les associer aux ressources suivantes :

- [VM (Virtual Machine)](/docs/compute/concept/)
- Interfaces réseaux
- [load balancers (équilibreurs de charge)](/docs/network/load-balancer/concepts/) reliés à Internet
- [nat gateways (passerelles NAT)](/docs/network/nat/concepts/)

Les IP publiques permettent de communiquer avec Internet.

:::info
Pour associer une IP publique dans un [VPC (Virtual Private Cloud)](/docs/network/vpc/concepts/), celui-ci doit avoir une [internet gateway (passerelle Internet)](/docs/network/internet-gateway/concepts/) attachée.
:::


Vous pouvez dissocier et réassocier une IP publique à n'importe quel moment. Par exemple, en cas de panne d'une VM, vous pouvez ainsi transférer l'IP publique vers une autre VM. La nouvelle VM a donc la même IP publique, ce qui signifie que les scripts et les applications qui utilisent cette IP publique ne rencontrent aucun problème.

Une IP publique dissociée reste allouée à votre compte. Si vous n'utilisez plus une IP publique, vous pouvez la libérer afin de la rendre disponible pour d'autres comptes.

:::warning

Assurez-vous qu'aucune application ou qu'aucun script n'utilise l'IP publique que vous voulez libérer.
:::

## Association des IP publiques

Vous ne pouvez associer une IP publique qu'à une seule ressource à la fois.

Si vous associez une IP publique à une VM ou à une interface réseau, avec la Console Numspot vous devez toujours dissocier l'IP publique avant de pouvoir la ré-associer à une autre ressource. Avec les API, vous pouvez configurer un comportement de ré-association : soit empêcher celle-ci, soit dissocier automatiquement l'IP publique et la ré-associer à la nouvelle VM ou interface réseau que vous spécifiez.

Si vous créez une NAT gateway, vous devez spécifier une IP publique. Pour modifier son IP publique, vous devez supprimer la NAT gateway puis la recréer avec la nouvelle IP publique.

Vous pouvez également associer une IP publique avec un load balancer relié à internet lorsque vous le gérez.

### Dans un VPC

L'IP publique s'attache à l'interface réseau principale de la VM. Si vous travaillez avec plusieurs interfaces réseau, vous pouvez choisir à laquelle des NIC (Network Interface Cards) vous souhaitez associer l'IP publique via l'API Numspot.

### Attribution automatique à la création d'une VM

Chaque subnet possède un attribut `mapPublicIpOnLaunch` qui détermine si une IP publique est attribuée automatiquement aux NIC créées dans le subnet, y compris la NIC principale créée au lancement d'une VM. Cet attribut est désactivé par défaut. Pour l'activer ou le désactiver, consultez [Modifier un attribut d'un subnet](/docs/network/subnets/actions/update/).

L'IP publique attribuée automatiquement présente les caractéristiques suivantes :

- elle est choisie de façon **aléatoire** : vous ne pouvez pas sélectionner l'adresse. Pour utiliser une IP publique précise, effectuez une [association manuelle](/docs/network/public-ip/actions/attach/) ;
- le lien entre l'IP publique et la VM persiste lors des arrêts et des redémarrages de la VM ;
- l'IP publique est **supprimée avec la VM** : elle est retournée au pool d'IP publiques et ne peut pas être dissociée individuellement ;
- elle **n'apparaît pas dans la section « IP publiques »** : elle n'est visible que dans les détails de la VM et de la NIC, et ne peut être ni dissociée, ni libérée, ni suivie depuis cette section ;
- elle est comptabilisée dans le quota d'IP publiques de votre compte.

:::info
Pour que les VM d'un subnet accèdent à Internet, le VPC doit avoir une [internet gateway](/docs/network/internet-gateway/concepts/) attachée, avec une route correspondante dans la [route table](/docs/network/route-table/concepts/) du subnet et des règles de [security group](/docs/compute/security-groups/concepts/concept-sg/) adaptées.
:::
