# Assigner une identité à un espace

Assignez des utilisateurs ou des comptes de service à un espace pour leur donner accès aux ressources de cet espace.

## Permissions

:::info
Cette action nécessite les permissions **IAM** (Identity and Access Management) suivantes :

- **iam.user.create**
- **iam.user.delete**
- **iam.serviceAccount.create**
- **iam.serviceAccount.delete**

Pour la variante depuis l'organisation décrite dans l'onglet API (assigner une identité à un espace depuis l'organisation), les permissions suivantes sont nécessaires à la place :

- **iam.space.update**
- **iam.user.update**
- **iam.serviceAccount.update**

L'assignation de l'identité requiert iam.space.update ; la modification des rôles et permissions de l'identité assignée requiert iam.user.update pour un compte utilisateur et iam.serviceAccount.update pour un compte de service.

:::

## API {#tabhead-api}

### Assigner une identité à un espace

Pour assigner un compte utilisateur à un espace avec l'API, il faut connaître l'UUID (Universally Unique Identifier) de l'espace. Une variante dans l'URL permet d'intervenir sur un utilisateur ou sur un compte de service.

À l'issue de cette opération, le compte sera assigné à l'espace mais sans rôle et permission.

https://docs.numspot.com/openapi/#tag/identity-access-management/POST/iam/spaces/{spaceId}/users/{userId}

```bash
curl 'https://api.{region}.numspot.com/iam/spaces/{spaceId}/users/{userId}' \
  --request POST
```

La requête ne retourne aucune réponse.

:::info
Consulter la [page sur l'utilisation des API](/docs/iam/concepts/api/) pour la mise en œuvre.
:::

Pour supprimer (enlever l'assignation) un compte utilisateur d'un espace avec l'API :

https://docs.numspot.com/openapi/#tag/identity-access-management/DELETE/iam/spaces/{spaceId}/users/{userId}

À l'issue de cette opération, le compte utilisateur ne sera plus assigné à l'espace mais sera toujours présent dans l'organisation ou assigné à d'autres espaces.

```bash
curl 'https://api.{region}.numspot.com/iam/spaces/{spaceId}/users/{userId}' \
  --request DELETE
```

Pour assigner un compte de service à un espace avec l'API :

https://docs.numspot.com/openapi/#tag/identity-access-management/POST/iam/spaces/{spaceId}/serviceAccounts/{serviceAccountId}

```bash
curl 'https://api.{region}.numspot.com/iam/spaces/{spaceId}/serviceAccounts/{serviceAccountId}' \
  --request POST
```

Pour supprimer (enlever l'assignation) un compte de service d'un espace avec l'API :

https://docs.numspot.com/openapi/#tag/identity-access-management/DELETE/iam/spaces/{spaceId}/serviceAccounts/{serviceAccountId}

À l'issue de cette opération, le compte de service ne sera plus assigné à l'espace mais sera toujours présent dans l'organisation ou assigné à d'autres espaces.

```bash
curl 'https://api.{region}.numspot.com/iam/spaces/{spaceId}/serviceAccounts/{serviceAccountId}' \
  --request DELETE
```

### Assigner une identité à un espace depuis l'organisation

Un administrateur d'organisation peut également assigner un compte utilisateur ou un compte de service à un espace directement depuis l'organisation, sans être lui-même assigné à cet espace. C'est ce qui lève le blocage à la création d'une organisation : son utilisateur d'origine peut affecter des identités à n'importe quel espace de l'organisation.

https://docs.numspot.com/openapi/#tag/identity-access-management/POST/iam/organisations/%7BorganisationId%7D/spaces/%7BspaceId%7D/%7BsubjectType%7D/%7BsubjectId%7D

`subjectType` vaut `users` ou `serviceAccounts`, et `subjectId` l'identifiant de l'identité à assigner. La requête retourne une réponse 201 sans contenu.

```bash
curl 'https://api.{region}.numspot.com/iam/organisations/{organisationId}/spaces/{spaceId}/users/{userId}' \
  --request POST
```

Une fois l'identité assignée, ses rôles et permissions sur cet espace se modifient avec l'endpoint de politique IAM, adressé lui aussi depuis l'organisation :

### Modifier les rôles et permissions de l'identité assignée

Pour un compte utilisateur :

https://docs.numspot.com/openapi/#tag/identity-access-management/PATCH/iam/organisations/%7BorganisationId%7D/spaces/%7BspaceId%7D/iampolicy/users/%7BsubjectId%7D

Pour un compte de service :

https://docs.numspot.com/openapi/#tag/identity-access-management/PATCH/iam/organisations/%7BorganisationId%7D/spaces/%7BspaceId%7D/iampolicy/serviceAccounts/%7BsubjectId%7D

Le corps de la requête ajoute ou retire des rôles et des permissions via les clés `add` et `delete`. Une politique est créée implicitement si l'identité n'en a pas encore sur cet espace.

```bash
curl 'https://api.{region}.numspot.com/iam/organisations/{organisationId}/spaces/{spaceId}/iampolicy/users/{userId}' \
  --request PATCH \
  --header 'Content-Type: application/json' \
  --data '{
    "add": {
      "roles": ["123e4567-e89b-12d3-a456-426614174001"],
      "permissions": ["123e4567-e89b-12d3-a456-426614174002"]
    }
  }'
```

La requête retourne une réponse 204 sans contenu. La même opération est disponible pour un compte de service, en remplaçant `users` par `serviceAccounts` et `userId` par l'identifiant du compte de service.
