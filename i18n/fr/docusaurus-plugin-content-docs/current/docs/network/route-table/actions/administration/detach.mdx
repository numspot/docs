# Détacher une route table d'un subnet

Vous pouvez détacher une [route table (table de routage)](/docs/network/route-table/concepts/) d'un subnet (sous-réseau). Ce subnet n'utilisera alors plus les routes contenues dans cette route table pour router le trafic réseau. Il utilisera les routes contenues dans la route table principale à la place, jusqu'à ce que vous l'associiez explicitement à une autre route table.

## Permissions

Aucune permission **IAM** (Identity and Access Management) n'est requise pour effectuer cette action.

## console {#tabhead-console}

:::info
**Avant de commencer :** Créez une route table. Pour en savoir plus, voir [Créer une route table ↗](../create.mdx). Il faut également qu'un subnet soit associé pour que l'action de dissocier soit proposée.
:::

1. Depuis le menu latéral gauche, cliquez sur **Réseau** → **[VPC](/docs/network/vpc/concepts/)** → **Route Tables** ;
2. Repérez la route table dont la colonne **Associations** indique au moins un subnet, puis ouvrez son menu **Actions** ;
3. Cliquez sur **Dissocier un Subnet**.

   Le panneau **Subnets** apparaît et liste les subnets associés à la route table ;
4. Cliquez sur **Dissocier** en face du subnet à détacher.

   Le subnet est dissocié : il utilise de nouveau la route table principale du VPC.

## api {#tabhead-api}

      La commande `PUT /compute/spaces/{spaceId}/routeTables/{id}/subnets/unlink` dissocie un subnet d'une route table.
Après la dissociation, le subnet ne peut plus utiliser les routes de cette route table, mais utilise celles de la route table principale du VPC à la place.

[Exemple de requête : Détacher une route table ↗](/openapi/#tag/compute/PUT/compute/spaces/{spaceId}/routeTables/{id}/subnets/unlink)
