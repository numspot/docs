# About client gateways

<ActionsSummary />

A client gateway sits on your side of a VPN (Virtual Private Network) connection, and manages the traffic between your corporate network and one of your [VPC (Virtual Private Cloud)](/docs/network/vpc/concepts/) in the Numspot Cloud.

Its counterpart on the Numspot side of the VPN connection is a [virtual gateway](/docs/connectivity/vpn/virtual-gateway/concepts/).

## General information

A client gateway is the entry and exit point to your corporate network on your side of the VPN connection.

![Architecture of a VPN Connection](/img/console/connectivity/vpn/sch-General-VPNConnectionArchitecture.png)
<p align="center">*Architecture of a VPN Connection*</p><br/>

You identify an existing resource in your network to use as a client gateway. It can be a software or hardware resource, for example a [VM](/docs/compute/concept/), a firewall or a router. When creating a client gateway, you must provide the following information:

* the static public IP of the resource you want to use as a client gateway;
* the routing type. To use dynamic routing, you must indicate an autonomous system number (ASN) for the BGP (Border Gateway Protocol) protocol. Otherwise, the routing is static.

You can have several client gateways in the same corporate network at the same time. This allows you, for example, to connect your corporate network to several of your VPC in the Numspot Cloud.

:::note
If you want to use different VPC simultaneously, you can create several client gateways with the same IP but a different ASN.
:::

## Lifecycle

A client gateway can be in one of the following states:

* `pending`: the creation process is in progress;
* `available`: the client gateway is created and ready to be used;
* `deleting`: the deletion process is in progress;
* `deleted`: the resource is no longer identified as a client gateway. However, the resource itself is not deleted.

:::info
Deleted resources remain visible for 1 hour.
:::
