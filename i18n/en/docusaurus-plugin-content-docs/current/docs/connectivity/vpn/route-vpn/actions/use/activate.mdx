# Enable route propagation

You can enable route propagation to a [route table](/docs/network/route-table/concepts/) so that it contains the routes associated with a VPN (Virtual Private Network) connection.

This action automatically updates the route table with the routes of the VPN connection, and directs them to the [virtual gateway](/docs/connectivity/vpn/virtual-gateway/concepts/). Otherwise, you must add each route to the route table manually. Route propagation is optional, and works with static or dynamic routing. You can use a default or custom route table.

## Permissions

:::info
This action requires the following IAM (Identity and Access Management) permissions:

- **connectivity.vpnconnection.update**

:::

<Tabs>
<TabItem value="console" label="Console" default>

:::warning
**Before you begin:**
* Create a [VPC](/docs/network/vpc/concepts/) (Virtual Private Cloud).
* Create a virtual gateway.
* Link the virtual gateway to the VPC.
* (optional) Create a custom route table for the subnet of the VPC.
:::

1. Click in the **Route Tables** dashboard to display checkboxes.
2. Select the route table for which you want to enable route propagation.
   The route table is selected and an actions menu appears.
3. Click **Enable route propagation**.
   The "Enable propagation by Virtual Gateway" dialog box is displayed.
4. In the "Virtual Gateway" list, select the virtual gateway whose routes you want to propagate.
5. Click **Enable**.
   Route propagation is enabled.

</TabItem>

The `PUT /compute/spaces/{spaceId}/routeTables/{id}/routePropagation` command configures route propagation to a specified route table of a VPC through a virtual gateway.
