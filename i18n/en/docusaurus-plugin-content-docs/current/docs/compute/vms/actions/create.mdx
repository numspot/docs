# Create a VM

You can create one or more custom [VM (Virtual Machine)](/docs/compute/concept/) within a [VPC (Virtual Private Cloud)](/docs/network/vpc/concepts/).

During creation, you can define the characteristics specific to each VM, such as the amount of RAM, the storage capacity and the number of vCPU (virtual Central Processing Unit).

To ensure security and authentication, all official images use [key pairs](/docs/compute/keypairs/concept/) as their authentication system. Therefore, to launch a VM from an official image, you must specify a valid key pair. Non-official images, however, may use different authentication systems. Consequently, before launching a VM from a non-official image, make sure to check whether a key pair is required or whether another authentication mechanism is provided.

## Permissions

:::info
This action requires the following **IAM** (Identity and Access Management) permissions:

- **Section:** compute — **Permission:** `vm.create` (create the VM)
- **Section:** compute — **Permission:** `vm.get` (view the VM after its creation)
- **Section:** compute — **Permission:** `vm.update` (start, stop or modify the VM after its creation)

:::

  1. From the left-hand side menu, click **Compute** → **VM** to access the list of VM.
  2. Click the **Create a VM** button at the top right of the screen to launch the VM creation wizard.


  Creating a VM in the Numspot console is simplified by a creation wizard that guides you through each configuration step.

  At each step, a summary of the selected options is displayed on the right-hand side of the screen, including the total estimated cost of the resources added. This lets you manage the costs of your VM and ensure they stay within your budget.

  The steps for creating a VM using the wizard are described below.

  ## Choose an image
  1. Select the OS image you want to use for your VM.


  2. Click **Continue**.  
  The "VM type" screen appears.

  ## Choose the type and number of VM
  1. Select the type of VM you want to create.


  Numspot offers VM templates optimized for various use cases: 

  - **Compute**: optimized for applications requiring high processing power;
  - **Memory**: optimized for applications requiring a large amount of RAM;
  - **Standard**: suitable for most use cases;
  - **Economy**: ideal for low-cost applications;
  - **Inference**: optimized for AI inference.

  2. Select the desired number of VM:


  - you can choose to create several VM simultaneously (up to a maximum of 20, subject to a quota increase); 
  - a summary of the selected options, with the total estimated cost, is displayed on the right-hand side of the screen. This lets you track the costs associated with your VM.

  3. Click **Continue**.  
  The "General information" and "Network" screen appears.

  ## Configure the general information and network

  ### Enter the general information

  1. In the "VM name" field, enter the name you want to assign to your VM or VM:
    - it must contain between 1 and 255 [printable ASCII characters](https://en.wikipedia.org/wiki/ASCII#Printable_characters);
    - it is used as a tag associated with your VM;
    - by default, all created VM have the same characteristics. They can be modified later.
  2. Tick the "Dedicated VM tenancy" box only if you want to create dedicated VM.  
  A dedicated VM benefits from dedicated hardware resources, for an additional cost.

  ### Configure the network

  Your VM must be attached to a VPC.

  1. Select one of the two options offered: use an existing VPC, or create a new VPC and its associated subnet:

  - if a VPC is already available in your space, select the desired VPC from the drop-down list, then choose an existing subnet from the "Subnet" drop-down list;
  - if no network exists yet, or if you want to create a new one, click the **Create a VPC** button;   
  A dialog box opens to create a new VPC and a new subnet:
    - to create the VPC, select the AZ (Availability Zone) in which you want to deploy your VM, enter the VPC name and then its IP (Internet Protocol) address range in CIDR (Classless Inter-Domain Routing) format;
    - to create the subnet, enter its name and then its IP address range in CIDR format;
  This address range must be part of the VPC range, without overlapping that of another subnet: 
    - click **Create the Network**.

  2. Click **Continue**.  
  The "System volume" screen appears.

  ## Configure the system volume

  1. Select one of the two options offered: "Continue with a default system volume" or "Customize the system volume".  
  To customize the system volume:
    1. Select one of the following values from the "Volume type" list:
      - "Magnetic" for a Magnetic volume;
      - "SSD" for a Performance volume;
      - "SSD premium" for an Enterprise volume. If you select "SSD premium", you must define the number of IOPS (Input/Output Operations Per Second) you need.
    2. In the "Volume size" field, specify the volume size (in GiB).  
  The minimum volume size is 10 GiB and the maximum size is 14901 GiB, subject to your quota. Make sure to choose a volume size suited to your storage and cost needs.
  2. Click **Continue**.  
  The "[Security group](/docs/compute/security-groups/concepts/concept-sg/)" screen appears.

  ## Configure the security group

  1. Select one of the three options offered: "Continue with the VPC security group", "Select one or more existing security groups" or "Create a new security group".
  2. To create a new security group, enter its name and description:
    - the name must be unique;
    - the security group name must not start with sg-; 
    - each name and description can contain between 1 and 255 characters. The allowed characters are a-z, A-Z, 0-9, space and \_.-:/()#,@\[\]+=&;!$\*.
  3. Click **Continue**.  
  The "Key pair" screen appears.

  ## Configure the key pair

  1. Select one of the three options offered:
    1. "Select an existing key pair"  
  Choose an existing key pair to connect to your VM.  
  Only RSA-format key pairs can decrypt the password of a Windows VM.
    2. "Create a new key pair"  
  In the "Key pair name" field, enter a name for the key pair:
      - the key pair name must be unique within your account;
      - it must contain between 1 and 255 [printable ASCII characters](https://en.wikipedia.org/wiki/ASCII#Printable_characters). You can download the private key at the last step of the VM creation.
    3. "Continue without a key pair"  
  This option lets you create a VM without a key pair. However, all official images use key pairs as their authentication system. So, if you want to access a VM created from an official image, you must associate a key pair with it during this step or later via the API.
  2. Click **Create the VM**.  
  The "Creation" screen appears.

  ## Finalize the VM creation

  - The resources to be created according to the selected options are automatically created and attached to your VM in sequential order;
  - if you chose to create a key pair, you must download the private key before leaving the creation screen.

:::warning
Save this file carefully. It cannot be recovered from Numspot if lost. Backing up and securely storing the key pair and associated passwords is the customer's responsibility.
:::

  - The screen displays the progress of the VM creation;
  - a summary of the selected options appears on the right-hand side of the screen. It includes:
    - the chosen image, the VM type, the general information (VM name, dedicated VM tenancy, etc.), the network (VPC and subnet), the volume (size and type), the security group and the key pair;
    - the summary also displays the total estimated cost of the VM, based on the selected options.
  - When the creation is complete, you can return to the list of VM.

## API {#tabhead-api}

Create and launch a VM from an image, within a space.

:::info
**Prerequisites**: a subnet must exist in the space ([create a subnet ↗](/docs/network/subnets/actions/create)); a [key pair](/docs/compute/keypairs/concept) and a [security group](/docs/compute/security-groups/concepts/concept-sg) are optional.

This operation requires an [access token](/docs/iam/concepts/api/) and the permissions listed at the top of the page.
:::

`POST https://api.eu-west-2.numspot.com/compute/spaces/{spaceId}/vms`

[Full documentation for this endpoint ↗](/openapi/#tag/compute/POST/compute/spaces/%7BspaceId%7D/vms)

### Parameters

| Parameter | Location | Required | Type | Example | Description |
| --- | --- | --- | --- | --- | --- |
| `imageId` | body | yes | string | `ami-12345678` | Identifier of the image to use; the image list is available through the ReadImages endpoint |
| `spaceId` | path | yes | UUID | `123e4567-e89b-12d3-a456-426614174000` | Space in which to create the VM |
| `subnetId` | body | yes | string | `subnet-12345678` | Subnet identifier in which to create the VM |
| `type` | body | yes | string | `ns-eco6-2c4r` | VM type among the 65 available |
| `blockDeviceMappings` | body | no | array | `/dev/sda1` | Block device mappings; each mapping describes a volume (`deviceName`, `bsu` with `deleteOnVmDeletion`, `iops`, `snapshotId`, `volumeSize`) |
| `bootOnCreation` | body | no | boolean | `true` | Start the VM on creation, `true` by default |
| `bsuOptimized` | body | no | boolean | — | Legacy parameter kept for compatibility, no effect |
| `clientToken` | body | no | string | `create-vm-2026-09` | Unique identifier managing the idempotency of the request |
| `deletionProtection` | body | no | boolean | `true` | Protects the VM against deletion when `true` |
| `keypairName` | body | no | string | `keypair-example` | Name of the key pair associated with the VM |
| `nestedVirtualization` | body | no | boolean | `false` | Enables nested virtualization (dedicated tenancy only) |
| `performance` | body | no | enum | `high` | `medium`, `high` or `highest`, `high` by default; ignored if the `type` template already carries its performance |
| `placement` | body | no | object | `{"tenancy": "default"}` | VM placement: `tenancy` (`default`, `dedicated` or dedicated group ID) and `availabilityZoneName` |
| `privateIps` | body | no | array | `10.0.0.4` | Private IP addresses of the VM |
| `securityGroupIds` | body | no | array | `sg-12345678` | Security group identifiers; the default security group applies if omitted |
| `securityGroups` | body | no | array | `my-security-group` | Security group names (alternative to `securityGroupIds`) |
| `userData` | body | no | string | `UHV0IHlvdXIgc2NyaXB0…` | Configuration script injected at startup, Base64-encoded, 500 KiB maximum |
| `vmInitiatedShutdownBehavior` | body | no | string | `stop` | Behavior when stopping: `stop` (default), `restart` or `terminate` |

The types used in this table are described in the [Parameter types](/docs/reference/parameter-types) page.

### Example

```bash
export TOKEN="{TOKEN}"

curl 'https://api.eu-west-2.numspot.com/compute/spaces/{SPACE-ID}/vms' \
  --request POST \
  --header "Authorization: Bearer $TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{
  "imageId": "{IMAGE-ID}",
  "subnetId": "{SUBNET-ID}",
  "type": "ns-eco6-2c4r",
  "keypairName": "{KEYPAIR-NAME}"
}'
```

| Variable | Represents | Where to find its value |
| --- | --- | --- |
| `{TOKEN}` | OAuth 2.0 access token of the request | Generated by the API authentication flow (see [Access token](/docs/iam/concepts/api/)) |
| `{SPACE-ID}` | Numspot space in which to create the VM | Numspot console (active space) or response of the [List spaces ↗](/docs/iam/space/actions/list) API |
| `{IMAGE-ID}` | Image used to create the VM | VM creation wizard in the console, or ReadImages API endpoint |
| `{SUBNET-ID}` | Subnet in which the VM is created | Numspot console (VPC network) or response of the subnet read API |
| `{KEYPAIR-NAME}` | Key pair associated with the VM | Numspot console or response of the key pair read API |

### Response

`201 Created` — the payload describes the created VM:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | VM identifier (`i-…`) |
| `state` | string | `pending`, `running`, `stopping`, `stopped`, `shutting-down`, `terminated` or `quarantine` |
| `type` | string | VM type |
| `imageId` | string | Image used |
| `subnetId` | string | Subnet of the VM |
| `keypairName` | string | Associated key pair |
| `privateIp` | string | Primary private IP address |
| `publicIp` | string | Public IP address, if allocated |
| `creationDate` | string | Creation date |

```json
{
  "id": "i-12345678",
  "state": "pending",
  "type": "ns-eco6-2c4r",
  "imageId": "ami-12345678",
  "subnetId": "subnet-12345678",
  "keypairName": "keypair-example",
  "privateIp": "10.0.0.4",
  "creationDate": "2026-09-21T10:15:30.485Z"
}
```

:::info
The VM is returned in the `pending` state, then moves to `running` once started. The metadata server provides the key pair's public key for password-less secure access.
:::

### Main errors

| Code | Case |
| --- | --- |
| 400 | Invalid body: unknown `type`, `userData` not Base64-encoded or too large, forbidden parameter combination |
| 401 | Access token missing, expired or invalid |
| 403 | Missing `vm.create` permission |
| 404 | Unknown `spaceId`, `imageId` or `subnetId` |
| 500 | Internal service error — retry later |

## Terraform {#tabhead-terraform}

Manage the VM with the `numspot_vm` resource of the [Numspot Terraform provider ↗](https://registry.terraform.io/providers/numspot/numspot/latest/docs). The provider authenticates with a service account's credentials (client_id / client_secret) and operates at space level.

:::info
**Prerequisites**: a subnet must exist in the space ([create a subnet ↗](/docs/network/subnets/actions/create)); a [key pair](/docs/compute/keypairs/concept) and a [security group](/docs/compute/security-groups/concepts/concept-sg) are optional.

The required permissions are listed at the top of the page.
:::

### Example

```hcl
terraform {
  required_providers {
    numspot = {
      source = "numspot/numspot"
    }
  }
}

variable "client_id" {
  type = string
}

variable "client_secret" {
  type      = string
  sensitive = true
}

provider "numspot" {
  client_id     = var.client_id
  client_secret = var.client_secret
}

resource "numspot_vm" "vm" {
  image_id           = "ami-0b7df82c"
  type               = "ns-eco6-2c8r"
  subnet_id          = "subnet-12345678"
  keypair_name       = "keypair-example"
  security_group_ids = ["sg-12345678"]
}
```

Replace the identifiers (`ami-…`, `subnet-…`, `sg-…`) with those of your own space.

| Variable | Represents | Where to find its value |
| --- | --- | --- |
| `var.client_id` | Service account identifier used by the provider | Created when the service account is created (Numspot console, IAM section) |
| `var.client_secret` | Service account secret | Generated when the service account is created, to be kept in a secrets manager |

### Arguments

| Argument | Required | Type | Example | Description |
| --- | --- | --- | --- | --- |
| `image_id` | yes | string | `ami-0b7df82c` | Identifier of the image to use (`ami-…`) |
| `subnet_id` | yes | string | `subnet-12345678` | Subnet identifier in which to create the VM |
| `type` | yes | string | `ns-eco6-2c8r` | VM type |
| `deletion_protection` | no | bool | `true` | Protects the VM against deletion when `true` |
| `initiated_shutdown_behavior` | no | string | `stop` | Behavior when stopping: `stop`, `restart` or `terminate` |
| `keypair_name` | no | string | `keypair-example` | Name of the key pair associated with the VM |
| `nested_virtualization` | no | bool | `false` | Enables nested virtualization (dedicated tenancy only) |
| `placement` | no | object | `{"tenancy": "default"}` | VM placement: `tenancy` and `availability_zone_name` |
| `private_ips` | no | list | `["10.0.0.4"]` | Private IP addresses of the VM |
| `security_group_ids` | no | set | `["sg-12345678"]` | Security group identifiers |
| `security_groups` | no | set | `["my-security-group"]` | Security group names (alternative to `security_group_ids`) |
| `tags` | no | set | `{key = "name", value = "my-vm"}` | Key/value tags associated with the VM |
| `user_data` | no | string | `UHV0IHlvdXIgc2NyaXB0…` | Configuration script injected at startup, Base64-encoded |

The types used in this table are described in the [Parameter types](/docs/reference/parameter-types) page.

### Import

If the VM already exists (created via the console or the API), import it into the Terraform state:

```bash
terraform import numspot_vm {VM-ID}
```

`{VM-ID}` is the VM ID (`i-…`, visible in the console or in the API response). The command attaches the existing VM to the matching `resource "numspot_vm"` block in your configuration, without modifying it. Terraform does not generate the configuration: afterwards, check with `terraform plan` that your configuration describes the actual state, or the next `apply` may destroy or modify the resource unexpectedly.
