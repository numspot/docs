# Link a route table to a subnet

You can link a [route table](/docs/network/route-table/concepts/) to one or more subnets of the [VPC (Virtual Private Cloud)](/docs/network/vpc/concepts/) for which it is created. The routes contained in the route table are then automatically applied to the [VM (Virtual Machine)](/docs/compute/concept/) placed in the subnet to route the network traffic.

## Permissions

:::info
This action requires the following **IAM** (Identity and Access Management) permissions:

- **compute.routeTable.update**

:::

:::info
**Prerequisite:** [Create a route table ↗](/docs/network/route-table/actions/create)
:::

1. From the left-hand side menu, click **Network** → **VPC** → **Route Table**.


2. Identify the route table that you want to associate with a subnet, then from the list of actions, click **Associate with a Subnet**.


    A new **Associate with a Subnet** dialog box appears.


3. Select the subnet that you want to associate with the route table.

4. Click the **Associate** button (multi-selection is available).


5. The subnet has been associated and the "The route table has been successfully associated with the subnet" message appears.


</TabItem>
<TabItem value="api">

The `PUT /compute/spaces/{spaceId}/routeTables/{id}/subnets/link` command associates a subnet with a route table. The subnet and the route table must be in the same VPC. Traffic is routed according to the route table defined in this VPC. You can associate a route table with several subnets.

[Request example: Link a route table ↗](/openapi/#tag/compute/PUT/compute/spaces/{spaceId}/routeTables/{id}/subnets/link)
