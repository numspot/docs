# Detach a route table from a subnet

You can detach a [route table](/docs/network/route-table/concepts/) from a subnet. This subnet will then no longer use the routes contained in this route table to route network traffic. It will use the routes contained in the main route table instead, until you explicitly associate it with another route table.

## Permissions

No IAM (Identity and Access Management) permission is required to perform this action.

<Tabs>
   <TabItem value="console" default> 

:::info
**Before you begin:** Create a route table. To find out more, see [Create a route table ↗](/docs/network/route-table/actions/create). A subnet must also be associated for the disassociation action to be available.
:::

1. From the left-hand side menu, click **Network** → **[VPC](/docs/network/vpc/concepts/)** → **Route Table**.
   ![menu_vpc.png](/img/console/network/vpc/en-menu_vpc.png)

2. Identify the route table you want to disassociate from a subnet, then click **Disassociate a Subnet** from the list of actions.
   ![actions_route_tables_full.png](/img/console/network/vpc/route-table/en-actions_route_tables_full.png)
   
   A new subnet disassociation dialog box appears.
   ![unlink_route_tables.png](/img/console/network/vpc/route-table/en-unlink_route_tables.png)

3. Select the subnet you want to disassociate from the route table.

4. Click **Disassociate**.
   ![unlink_route_tables_cta.png](/img/console/network/vpc/route-table/en-unlink_route_tables_cta.png)

5. A strong confirmation dialog box appears.
   ![unlink_route_tables_confirm.png](/img/console/network/vpc/route-table/en-unlink_route_tables_confirm.png)

6. Click **Disassociate the Subnet**.
   ![unlink_route_tables_cta_2.png](/img/console/network/vpc/route-table/en-unlink_route_tables_cta_2.png)

7. The subnet has been disassociated and the following message appears:
   ![unlink_route_tables_success.png](/img/console/network/vpc/route-table/unlink_route_tables_success.png)
