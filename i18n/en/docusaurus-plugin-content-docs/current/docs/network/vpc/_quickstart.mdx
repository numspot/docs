# Quickstart with VPC (Virtual Private Cloud)

As part of this cloud infrastructure, you will set up a private and secure virtual network, called a [VPC (Virtual Private Cloud)](/docs/network/vpc/concepts/). 
This VPC will be the dedicated network environment for your cloud resources, allowing you to control and manage your network traffic effectively.

## Create a Numspot account

If you do not yet have a Numspot account, sign up on [Numspot](https://www.numspot.com/) to create one. 
Fill in the required information and confirm your email address.

## Log in to the Numspot console

Go to the Numspot website and log in to your account using your email address and password. 
![Login](/img/screenshot/login.png)

Type the 6-digit code you received on your authentication application.
![TOTP](/img/screenshot/totp.png)

Then access the Numspot console.
![Dashboard](/img/screenshot/dashboard.png)

## Create a VPC
You will define a CIDR (Classless Inter-Domain Routing) block of 192.168.0.0/16 for your VPC.
This will provide a wide range of IP (Internet Protocol) addresses (2^16 = 65536) that you can use for your instances, databases, and other cloud resources.

1. In the VPC dashboard, click the **Create a VPC** button. A new window appears.
2. In the "Name" field, enter a name for the VPC (for example, `NS_Lab`).
3. In the "IP range" field, enter the range `192.168.0.0/16` for your VPC.

![Create VPC](/img/screenshot/create_vpc_01.png)
Click **Create a VPC**. The VPC is created.

![List VPC](/img/screenshot/list_vpc.png)

## Create a subnet
Next, you will create a subnet within your VPC. 
A subnet is a subdivision of an IP network, which allows you to segment your VPC into several smaller and more manageable networks. 
You will define a CIDR block of 192.168.0.0/24 for your subnet, which will give 2^8 = 256 IP addresses.

1. Click the "ID" of the VPC. A new window appears, containing your VPC information.
2. Click **Create a subnet**
   ![VPC details](/img/screenshot/vpc_details.png)
3. In the "Name" field, enter a name for the subnet.
4. In the CIDR field, enter the range `192.168.0.0/24` for your subnet (for example, `NS_Subnet_1`).
5. From the "Availability zone" list, select the zone in which you want to create the subnet.
   ![Create Subnet](/img/screenshot/create_subnet.png)

Click **Create a subnet**. The subnet is created in the VPC.

## Create an internet gateway (IGW)
To allow your instances located in the VPC to access the Internet and vice versa, you will create an [internet gateway](/docs/network/internet-gateway/concepts/) and attach it to your VPC. 
The IGW is a component that provides a gateway for inbound and outbound network traffic.

![Create IGW](/img/screenshot/create_igw.png)

1. In the Internet Gateway dashboard, click **Create an IGW**.
   <br/>A new "Create an internet gateway" window appears.
2. In the "Name" field, type a name (for example, `NS_IGW`) for the internet gateway.
   <br/>Click **Create an IGW**. The internet gateway is created. 

Next, you will attach the internet gateway to your VPC.

![Link IGW to VPC](/img/screenshot/link_igw_vpc.png)
1.	Click inside the Internet Gateway dashboard, then select the internet gateway you want to link.
2.	Click **Link to a VPC**. The "Link to a VPC" dialog box appears.
3.	Select the VPC (`NS_Lab`) from the list of VPC.
4.	Click **Link**.
   ![Link IGW to VPC](/img/screenshot/link_igw_vpc_1.png)
The internet gateway is linked to the VPC.

## Create a route table and associate it with a subnet

You will create a [route table](/docs/network/route-table/concepts/), associate it with your subnet, and add a route that directs all outbound traffic (`0.0.0.0/0`) to the IGW. 
A route table is a set of rules that determine where network traffic is directed, which allows you to control and manage your network traffic effectively.
:::tip
Create separate route tables for your different subnets. 
This will allow you to better control inbound and outbound network traffic for each subnet.
:::
:::warning
Avoid putting all routes in the default main route table. 
This can cause routing conflicts and network connectivity issues. 

Instead, create separate route tables for your different subnets and associate them with the appropriate subnets.
:::

### Create a route table

![Create Route Table](/img/screenshot/create_route_table.png)

1. In the Route Tables dashboard, click the **Create a route table** button. A new window appears.
2. In the "Name" field, enter a name (for example, `NS_RT_Subnet_1`).
3. Select the VPC to which you want to associate the route table (for example, `NS_Lab`).
4.	Click **Create**.
   <br/>The route table is created.

### Add a route
1. Click the routes link corresponding to the created route table. The "Create routes" pane appears.
   ![Create Route Table](/img/screenshot/add_route_1.png)
2. Click **Add a route**. A new window appears.
3. From the "Type" drop-down menu, select "Internet Gateway".
4. From the "Target" drop-down menu, select the IGW you created earlier (`NS_IGW`).
5. In the Destination field, enter `0.0.0.0/0` by clicking **All IPS**.
6. Click **Add route** then **Validate**.
   ![Create Route Table](/img/screenshot/add_route_2.png)
   <br/> The route appears in the list of routes for the route table.

:::note
* By creating separate route tables for your different subnets, you can better control inbound and outbound network traffic for each subnet. 
* This also allows you to better manage your network security by using [security groups](/docs/compute/security-groups/concepts/concept-sg/) to control inbound and outbound network traffic for your instances.
* It is therefore important to carefully plan your VPC network and define subnets and route tables according to your network connectivity and security requirements.
:::

### Associate a route table with a subnet

1. In the Route tables dashboard, identify the route table to which you want to associate a subnet.
2. From the "Actions" menu, select **Associate to a subnet**.
    ![Associate Route Table to Subnet](/img/screenshot/associate_rt_subnet_1.png)
  <br/> A "Subnets" side dialog pane will appear.
3. Select the subnet you want to associate with the route table, then click **Associate**.
   ![Associate Route Table to Subnet](/img/screenshot/associate_rt_subnet_2.png)
   <br/>The route table is associated with the subnet.

With this configuration, you will have a robust, secure and scalable VPC platform for your cloud infrastructure.
