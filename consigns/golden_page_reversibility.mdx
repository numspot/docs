# Reversibility of managed Kubernetes

<!-- Link the general policy once instead of restating its principles. -->

This page describes how to export your data and leave the [managed Kubernetes](/docs/managed-services/kubernetes/concepts/) service, in application of the [general reversibility policy](/docs/support/reversibility/global-reversibility-policy).

## Exportable data

<!-- Everything the customer can take away: resources, data, configuration.
     Name the formats (YAML manifests, database dumps…). -->

- the cluster resources (deployments, services, config maps), exported as YAML manifests;
- the persistent data, through the storage backup mechanisms;
- the `kubeconfig` file, to reconnect the same tooling elsewhere.

## Exit procedure

<!-- The numbered sequence, end to end. Order matters: what to export
     first, what to shut down last. -->

1. Export the cluster resources and verify the manifests;
2. Back up the persistent data and test the restore on the target platform;
3. Delete the cluster when the migration is confirmed.

:::info
The export is customer-run: Numspot provides standard tooling and open formats but does not operate the migration. See the [general reversibility policy](/docs/support/reversibility/global-reversibility-policy) for the responsibility split.
:::
