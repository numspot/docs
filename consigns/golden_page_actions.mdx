# Créer une VM

<!-- The theme renders the review date right under this H1 ("Mise à jour le
     <date>" FR / "Reviewed on <date>" EN) from the `last_update.date`
     frontmatter above — do NOT write the date line in the page body.

Vous pouvez créer une ou plusieurs [VM](/docs/compute/concept) (Virtual Machine) sur mesure au sein d'un [VPC](/docs/network/vpc/concepts) (Virtual Private Cloud).

Lors de la création, vous pouvez définir les caractéristiques propres à chaque VM, telles que la taille de la mémoire vive, la capacité de stockage et le nombre de vCPU (virtual Central Processing Unit).

Pour garantir la sécurité et l'authentification, toutes les images officielles utilisent des [key pairs](/docs/compute/keypairs/concept) (paires de clés) comme système d'authentification. Ainsi, pour lancer une VM à partir d'une image officielle, il est essentiel de spécifier une key pair valide. En revanche, les images non-officielles peuvent avoir recours à différents systèmes d'authentification. Par conséquent, avant de lancer une VM à partir d'une image non-officielle, assurez-vous de vérifier si l'utilisation d'une key pair est requise ou si un autre mécanisme d'authentification est prévu.

## Permissions

:::info
Cette action nécessite les permissions IAM suivantes :

- **Section :** compute — **Permission :** `vm.create` (créer la VM)
- **Section :** compute — **Permission :** `vm.get` (consulter la VM après sa création)
- **Section :** compute — **Permission :** `vm.update` (démarrer, arrêter ou modifier la VM après sa création)

:::

   <TabItem value="console" label="Console" default> 

  :::info
  **Prérequis optionnels**
  - [Créer un VPC ↗](../../../network/vpc/actions/create.mdx)
  - [Créer un subnet ↗](../../../network/subnets/actions/create.mdx)
  - [Créer un security group ↗](../../security-groups/actions/create.mdx) 
  - [Créer une key pair ↗](../../keypairs/actions/create.mdx)

  1. Depuis le menu latéral gauche, cliquez sur **Compute** → **VM** pour accéder à la liste des VM.
  2. Cliquez sur le bouton **Créer une VM** situé en haut à droite de l'écran pour lancer l'assistant de création de VM.

![menu_compute.png](/img/console/compute/menu_compute.png)

  La création d'une VM sur la console Numspot est simplifiée grâce à un assistant (wizard) qui vous guide à travers chaque étape de configuration.

  À chaque étape un récapitulatif des options sélectionnées est affiché sur le côté droit de l'écran, incluant le coût total estimé des ressources ajoutées. Cela vous permet de gérer facilement les coûts de votre VM et de vous assurer qu'ils restent dans les limites de votre budget.

  Vous trouverez ci-après les étapes de création d'une VM en utilisant l'assistant.

  ## Choisir une image

  1. Sélectionnez l'image de l'OS que vous souhaitez utiliser pour votre VM.

  ![Image Selection](/img/console/compute/vms/image_selection_vm.png)

  2. Cliquez sur **Continuer**.  
  L'écran du "Type de VM" apparaît.

  ## Choisir le type et le nombre de VM

  1. Sélectionnez le type de VM que vous souhaitez créer.

![Type Selection VM](/img/console/compute/vms/type_selection_vm.png)

  Numspot vous propose des gabarits de VM optimisés pour divers cas d'utilisation : 

  - **Calcul** : Optimisé pour les applications nécessitant une puissance de traitement élevée ;
  - **Mémoire** : Optimisé pour les applications nécessitant une grande quantité de mémoire vive ;
  - **Standard** : Convient à la plupart des cas d'utilisation ;
  - **Économique** : Idéal pour les applications à faible coût ;
  - **Inference** : Optimisé pour l'entraînement d'IA.

  2. Sélectionnez le nombre de VM souhaité :

![Number of VM](/img/console/compute/vms/number_of_vms.png)

  - vous pouvez choisir de créer plusieurs VM simultanément (jusqu'à un maximum de 20, sous réserve d'augmentation de quota) ; 
  - un récapitulatif des options sélectionnées, avec le coût total estimé, est affiché sur le côté droit de l'écran. Cela vous permet de suivre facilement les coûts associés à votre VM.

  3. Cliquez sur **Continuer**.  
  L'écran des "Informations générales" et du "Réseau" apparaît.

  ## Configurer les informations générales et le réseau

![General Information VM](/img/console/compute/vms/general_information_vm.png)

  ### Renseignez les informations générales

  1. Dans le champ "Nom de la VM", renseignez le nom que vous souhaitez attribuer à votre ou vos VM :
    - il doit contenir entre 1 et 255 [caractères ASCII imprimables](https://fr.wikipedia.org/wiki/American_Standard_Code_for_Information_Interchange#Caract%C3%A8res_imprimables) ;
    - il est utilisé comme tag associé à vos VM ;
    - par défaut toutes les VM créées ont les mêmes caractéristiques. Elles peuvent être modifiées ultérieurement.
  2. Cochez la case "Bail de VM dédié" uniquement si vous souhaitez créer des VM dédiées.  
  Cette option vous permet de bénéficier d'une VM dédiée avec des ressources garanties, moyennant un coût supplémentaire.

  ### Configurez le réseau

  Votre VM doit être rattachée à un VPC (Virtual Private Cloud).

  1. Sélectionnez l'une des deux options proposées : utiliser un VPC existant ou créer un nouveau VPC et son subnet (sous-réseau) associé :

  - Si un VPC est déjà disponible dans votre espace, sélectionnez le VPC souhaité dans la liste déroulante, puis choisissez ensuite un subnet existant dans la liste déroulante "Subnet" ;
  - Si aucun réseau n'existe encore ou si vous souhaitez en créer un nouveau, cliquez sur le bouton **Créer un VPC** ;   
  Une boîte de dialogue s'ouvre pour créer un nouveau VPC et un nouveau subnet :
    - Pour créer le VPC, sélectionnez l'AZ (Availability Zone) dans laquelle vous souhaitez déployer votre VM, renseignez le nom du VPC puis sa plage d'adresses IP au format CIDR ;
    - Pour créer le subnet, renseignez son nom puis sa plage d'adresses IP au format CIDR ;
  Cette plage d'adresses doit faire partie de la plage du VPC, sans chevaucher celle d'un autre subnet : 
    - Cliquez sur **Créer le Network**.

  2. Cliquez sur **Continuer**.  
  L'écran de "Volume système" apparaît.

  ## Configurer le volume système

![Volume système VM](/img/console/compute/vms/volume_system_vm.png)

  1. Sélectionnez l'une des deux options proposées : "Poursuivre avec un Volume système par défaut" ou "Personnaliser le Volume système".  
  Pour personnaliser le volume système :
    1. Sélectionnez l'une des valeurs suivantes dans la liste "Type de volume" :
      - "Magnetic" pour un volume Magnetic ;
      - "SSD" pour un volume Performance ;
      - "SSD premium" pour un volume Enterprise. Si vous sélectionnez "SSD premium", vous devez définir le nombre d'IOPS dont vous avez besoin.
    2. Dans le champ "Taille du volume", spécifiez la taille du volume (en Gio).  
  La taille minimale du volume est de 10 Gio et la taille maximale est de 14901 Gio, sous réserve de votre quota. Assurez-vous de choisir une taille de volume adaptée à vos besoins en termes de stockage et de coût.
  2. Cliquez sur **Continuer**.  
  L'écran de "Security Group" (groupe de sécurité) apparaît.

  ## Configurer le security group

![Security Group](/img/console/compute/vms/security_group_vm.png)

  1. Sélectionnez l'une des trois options proposées : "Continuez avec le Security Group du VPC", "Sélectionnez un ou plusieurs Security Groups existants" ou "Créez un nouveau Security Group".
  2. Pour créer un nouveau [security group](/docs/compute/security-groups/concepts/concept-sg), renseignez son nom et sa description :
    - le nom doit être unique ;
    - le nom du security group ne doit pas commencer par sg- ; 
    - chaque nom et description peut contenir entre 1 et 255 caractères. Les caractères autorisés sont a-z, A-Z, 0-9, l'espace et \_.-:/()#,@\[\]+=&;!\$\*.
  3. Cliquez sur **Continuer**.  
  L'écran de "Key pair" (paire de clés) apparaît.

  ## Configurer la key pair

![Keypair](/img/console/compute/vms/keypair_vm.png)

  1. Sélectionnez l'une des trois options proposées :
    1. "Sélectionner une key pair existante"  
  Choisissez une key pair existante pour vous connecter à votre VM.  
  Seules les key pairs au format RSA peuvent déchiffrer le mot de passe d'une VM Windows.
    2. "Créer une nouvelle key pair"  
  Dans le champ "Nom de la key pair", renseignez un nom pour la key pair :
      - le nom de la key pair doit être unique dans votre compte ;
      - il doit contenir entre 1 et 255 [caractères ASCII imprimables](https://fr.wikipedia.org/wiki/American_Standard_Code_for_Information_Interchange#Caract%C3%A8res_imprimables). Vous pourrez télécharger la clé privée à la dernière étape de la création de la VM.
    3. "Continuer sans key pair"  
  Cette option vous permet de créer une VM sans key pair. Néanmoins toutes les images officielles utilisent des key pairs comme système d'authentification. Si vous voulez accéder à une VM créée à partir d'une image officielle vous devez donc y associer une key pair pendant cette étape ou plus tard via l'API.
  2. Cliquez sur **Créer la VM**.  
  L'écran de "Création" s'affiche.

  ## Finaliser la création de la VM

![Creation done](/img/console/compute/vms/creation_done_vm.png)

  - Les ressources à créer selon les options sélectionnées seront automatiquement créées et rattachées à votre VM dans un ordre séquentiel ;
  - Si vous avez choisi de créer une key pair, vous devrez télécharger la clé privée avant de quitter l'écran de création.

:::warning
Sauvegardez ce fichier avec précaution, car vous aurez besoin de son contenu à chaque connexion à vos ressources. Il ne peut pas être récupéré auprès de Numspot en cas de perte.
:::

  - L'écran affiche l'évolution de la création de la VM ;
  - Un récapitulatif des options sélectionnées apparaît sur le côté droit de l'écran. Il inclut :
    - l'image choisie, le type de VM, les informations générales (nom de la VM, bail de VM dédié, etc.), le réseau (VPC et subnet), le volume (taille et type), le security group et la key pair ;
    - le récapitulatif affiche également le coût total estimé de la VM, basé sur les options sélectionnées.
  - Lorsque la création est terminée, vous pouvez retourner à la liste des VM.
</TabItem>

## API {#tabhead-api}

Créez et lancez une VM à partir d'une image, au sein d'un espace.

:::info
**Prérequis** : un subnet doit exister dans l'espace (créer un [subnet ↗](/docs/network/subnets/actions/create)) ; une [key pair](/docs/compute/keypairs/concept) et un [security group](/docs/compute/security-groups/concepts/concept-sg) sont optionnels.

Cette opération nécessite un [jeton d'accès](/docs/iam/concepts/api/) et les permissions listées en tête de page.
:::

`POST https://api.eu-west-2.numspot.com/compute/spaces/{spaceId}/vms`

[Documentation complète de cet endpoint ↗](/openapi/#tag/compute/POST/compute/spaces/%7BspaceId%7D/vms)

### Paramètres

| Paramètre | Emplacement | Requis | Type | Exemple | Description |
| --- | --- | --- | --- | --- | --- |
| `imageId` | corps | oui | string | `ami-12345678` | Identifiant de l'image à utiliser ; la liste des images est disponible via l'endpoint ReadImages |
| `spaceId` | chemin | oui | UUID | `123e4567-e89b-12d3-a456-426614174000` | Espace dans lequel créer la VM |
| `subnetId` | corps | oui | string | `subnet-12345678` | Identifiant du subnet dans lequel créer la VM |
| `type` | corps | oui | string | `ns-eco6-2c4r` | Gabarit de VM parmi les 65 disponibles |
| `blockDeviceMappings` | corps | non | array | `/dev/sda1` | Mappings de périphériques blocs ; chaque mapping décrit un volume (`deviceName`, `bsu` avec `deleteOnVmDeletion`, `iops`, `snapshotId`, `volumeSize`) |
| `bootOnCreation` | corps | non | boolean | `true` | Démarrage de la VM à la création, `true` par défaut |
| `bsuOptimized` | corps | non | boolean | — | Paramètre historique conservé pour compatibilité, sans effet |
| `clientToken` | corps | non | string | `create-vm-2026-09` | Identifiant unique gérant l'idempotence de la requête |
| `deletionProtection` | corps | non | boolean | `true` | Empêche la suppression de la VM si `true` |
| `keypairName` | corps | non | string | `keypair-example` | Nom de la key pair associée à la VM |
| `nestedVirtualization` | corps | non | boolean | `false` | Active la virtualisation imbriquée (bail dédié uniquement) |
| `performance` | corps | non | enum | `high` | `medium`, `high` ou `highest`, `high` par défaut ; ignoré si le gabarit `type` porte déjà sa performance |
| `placement` | corps | non | object | `{"tenancy": "default"}` | Placement de la VM : `tenancy` (`default`, `dedicated` ou ID de groupe dédié) et `availabilityZoneName` |
| `privateIps` | corps | non | array | `10.0.0.4` | Adresses IP privées de la VM |
| `securityGroupIds` | corps | non | array | `sg-12345678` | Identifiants des security groups ; le security group par défaut est appliqué si absent |
| `securityGroups` | corps | non | array | `mon-security-group` | Noms des security groups (alternative à `securityGroupIds`) |
| `userData` | corps | non | string | `UHV0IHlvdXIgc2NyaXB0…` | Script de configuration injecté au démarrage, encodé en Base64, 500 KiB maximum |
| `vmInitiatedShutdownBehavior` | corps | non | string | `stop` | Comportement à l'arrêt : `stop` (défaut), `restart` ou `terminate` |

Les types utilisés dans ce tableau sont décrits dans la page [Types de paramètres](/docs/reference/parameter-types).

### Exemple

```bash
export TOKEN="{TOKEN}"

curl 'https://api.eu-west-2.numspot.com/compute/spaces/{SPACE-ID}/vms' \
  --request POST \
  --header "Authorization: Bearer $TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{
  "imageId": "{IMAGE-ID}",
  "subnetId": "{SUBNET-ID}",
  "type": "ns-eco6-2c4r",
  "keypairName": "{KEYPAIR-NAME}"
}'
```

| Variable | Représente | Où trouver sa valeur |
| --- | --- | --- |
| `{TOKEN}` | Jeton d'accès OAuth 2.0 de la requête | Généré par l'authentification API (voir [Jeton d'accès](/docs/iam/concepts/api/)) |
| `{SPACE-ID}` | Espace Numspot dans lequel créer la VM | Console Numspot (espace actif) ou réponse de l'API [Lister les espaces ↗](/docs/iam/space/actions/list) |
| `{IMAGE-ID}` | Image utilisée pour créer la VM | Assistant de création de VM sur la console, ou endpoint ReadImages de l'API |
| `{SUBNET-ID}` | Subnet dans lequel la VM est créée | Console Numspot (réseau du VPC) ou réponse de l'API de lecture des subnets |
| `{KEYPAIR-NAME}` | Key pair associée à la VM | Console Numspot ou réponse de l'API de lecture des key pairs |

### Réponse

`201 Created` — le payload décrit la VM créée :

| Champ | Type | Description |
| --- | --- | --- |
| `id` | string | Identifiant de la VM (`i-…`) |
| `state` | string | `pending`, `running`, `stopping`, `stopped`, `shutting-down`, `terminated` ou `quarantine` |
| `type` | string | Gabarit de la VM |
| `imageId` | string | Image utilisée |
| `subnetId` | string | Subnet de la VM |
| `keypairName` | string | Key pair associée |
| `privateIp` | string | Adresse IP privée principale |
| `publicIp` | string | Adresse IP publique, si attribuée |
| `creationDate` | string | Date de création |

```json
{
  "id": "i-12345678",
  "state": "pending",
  "type": "ns-eco6-2c4r",
  "imageId": "ami-12345678",
  "subnetId": "subnet-12345678",
  "keypairName": "keypair-example",
  "privateIp": "10.0.0.4",
  "creationDate": "2026-09-21T10:15:30.485Z"
}
```

:::info
La VM est retournée avec l'état `pending`, puis passe à `running` une fois démarrée. Le serveur de métadonnées fournit la clé publique de la key pair pour un accès sécurisé sans mot de passe.
:::

### Erreurs principales

| Code | Cas |
| --- | --- |
| 400 | Corps invalide : `type` inconnu, `userData` non encodé en Base64 ou trop volumineux, combinaison de paramètres interdite |
| 401 | Jeton d'accès absent, expiré ou invalide |
| 403 | Permission `vm.create` manquante |
| 404 | `spaceId`, `imageId` ou `subnetId` inconnu |
| 500 | Erreur interne du service — réessayer plus tard |

## Terraform {#tabhead-terraform}

Gérez la VM avec la ressource `numspot_vm` du [provider Terraform Numspot ↗](https://registry.terraform.io/providers/numspot/numspot/latest/docs). Le provider s'authentifie avec les identifiants d'un compte de service (client_id / client_secret) et opère au niveau de l'espace configuré.

:::info
**Prérequis** : un subnet doit exister dans l'espace (créer un [subnet ↗](/docs/network/subnets/actions/create)) ; une [key pair](/docs/compute/keypairs/concept) et un [security group](/docs/compute/security-groups/concepts/concept-sg) sont optionnels.

Les permissions nécessaires sont listées en tête de page.
:::

### Exemple

```hcl
terraform {
  required_providers {
    numspot = {
      source = "numspot/numspot"
    }
  }
}

variable "client_id" {
  type = string
}

variable "client_secret" {
  type      = string
  sensitive = true
}

provider "numspot" {
  client_id     = var.client_id
  client_secret = var.client_secret
}

resource "numspot_vm" "vm" {
  image_id           = "ami-0b7df82c"
  type               = "ns-eco6-2c8r"
  subnet_id          = "subnet-12345678"
  keypair_name       = "keypair-example"
  security_group_ids = ["sg-12345678"]
}
```

Remplacez les identifiants (`ami-…`, `subnet-…`, `sg-…`) par ceux de votre espace.

| Variable | Représente | Où trouver sa valeur |
| --- | --- | --- |
| `var.client_id` | Identifiant du compte de service utilisé par le provider | Créé lors de la création du compte de service (console Numspot, section IAM) |
| `var.client_secret` | Secret du compte de service | Généré à la création du compte de service, à conserver dans un gestionnaire de secrets |

### Arguments

| Argument | Requis | Type | Exemple | Description |
| --- | --- | --- | --- | --- |
| `image_id` | oui | string | `ami-0b7df82c` | Identifiant de l'image à utiliser (`ami-…`) |
| `subnet_id` | oui | string | `subnet-12345678` | Identifiant du subnet dans lequel créer la VM |
| `type` | oui | string | `ns-eco6-2c8r` | Gabarit de VM |
| `deletion_protection` | non | bool | `true` | Empêche la suppression de la VM si `true` |
| `initiated_shutdown_behavior` | non | string | `stop` | Comportement à l'arrêt : `stop`, `restart` ou `terminate` |
| `keypair_name` | non | string | `keypair-example` | Nom de la key pair associée à la VM |
| `nested_virtualization` | non | bool | `false` | Active la virtualisation imbriquée (bail dédié uniquement) |
| `placement` | non | object | `{"tenancy": "default"}` | Placement de la VM : `tenancy` et `availability_zone_name` |
| `private_ips` | non | list | `["10.0.0.4"]` | Adresses IP privées de la VM |
| `security_group_ids` | non | set | `["sg-12345678"]` | Identifiants des security groups |
| `security_groups` | non | set | `["mon-security-group"]` | Noms des security groups (alternative à `security_group_ids`) |
| `tags` | non | set | `{key = "name", value = "ma-vm"}` | Tags key/value associés à la VM |
| `user_data` | non | string | `UHV0IHlvdXIgc2NyaXB0…` | Script de configuration injecté au démarrage, encodé en Base64 |

Les types utilisés dans ce tableau sont décrits dans la page [Types de paramètres](/docs/reference/parameter-types).

### Import

Si la VM existe déjà (créée via la console ou l'API), importez-la dans l'état Terraform :

```bash
terraform import numspot_vm {VM-ID}
```

`{VM-ID}` est l'identifiant de la VM (`i-…`, visible sur la console ou en réponse de l'API). La commande associe la VM existante au bloc `resource "numspot_vm"` correspondant dans votre configuration, sans la modifier. Terraform n'importe pas les attributs dans la configuration : vérifiez ensuite avec `terraform plan` que la configuration décrit bien l'état réel, sous peine de destruction ou de modification non souhaitée au prochain `apply`.
